# 后端与本地识别

后端使用 Python 3.11+ 标准库 HTTP 服务和 SQLite，适合这次小规模单会期资料收集。PDF 文字提取、图像校验和 Excel 导出分别使用 pypdf、Pillow、openpyxl。文件和数据库均保存在 `data/`，不会作为网页静态文件公开。

## 启动

在本目录中安装依赖后运行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --port 8765
```

默认嘉宾邀请码为 `01AI2026VIP`，可通过 `GUEST_INVITE_CODE`（至少 6 位）环境变量覆盖。首次启动自动生成管理员密码，仅在终端显示一次；后续可通过 `ADMIN_PASSWORD`（至少 12 位）环境变量重新设置。`data/config.json` 只保存加盐密码哈希，不要把真实管理员密码或环境配置写入 GitHub。正式大会名称通过 `EVENT_NAME` 设置。启动默认仅监听 `127.0.0.1`。

在本机 Codex 内可使用预装运行时，无需安装核心依赖：

```sh
/Users/admin/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 server.py --port 8765
```

## OCR 能力与边界

- 电子 PDF 优先提取原始文字；图片与扫描 PDF 使用 PaddleOCR。本机已安装并用虚构票据实际验证 PaddlePaddle 3.3.1、PaddleOCR 3.7.0，使用 `PP-OCRv5_mobile_det` 与 `PP-OCRv5_mobile_rec` CPU 模型。
- 交通电子发票按票面类型解析：铁路电子客票读取票价；航空运输电子客票行程单读取合计及明确标注的税额，使用填开日期而非乘机/有效截止日期。表格中的货币金额通过同页列位置关联，无法明确对应时留空。OCR 响应附带 `documentType`、`documentLabel`、`suggestedCategory`；类别建议仅填补未选择的费用类型。
- 输出 9 个字段：发票号码 `invoiceNumber`、开票日期 `date`、购买方名称 `buyerName`、购买方税号 `buyerTaxId`、销售方名称 `sellerName`、销售方税号 `sellerTaxId`、不含税金额 `netAmount`、税额 `taxAmount`、含税总额 `amount`。结合票面标签和文字位置区分购销双方，含税总额用于报销金额。
- 本机环境为 `.venv-paddle/`，模型缓存在 `.runtime/paddle/paddlex/official_models/`，已验证版本与路径记录在 `.runtime/paddle-ready.json`。`start.command` 检测到环境和就绪标记后优先使用该 Python。缓存默认保存在项目 `.runtime/paddle/`，不写入公共静态目录。
- `start.command` 在具备 Swift 编译器的 macOS 上准备 `scripts/vision_ocr.swift`，编译至被 Git 忽略的 `.runtime/vision-ocr`；PaddleOCR 未完成时自动尝试 Apple Vision 离线后备识别，也可用 `OCR_ENGINE=vision` 指定。当前电脑已完成此准备；Linux/Windows 无此后备引擎。
- 扫描 PDF 的 PaddleOCR 与 Apple Vision 路径均最多识别前 5 页，建议按票据拆分上传；原始 PDF 保留用于人工核对和归档。
- 本机模型已下载，实际票据识别在运行网站的电脑或服务器本地完成，不调用第三方 OCR API。迁移环境后需安装 `requirements-ocr.txt` 并提前准备官方模型；首次模型准备可能联网，正式活动前应完成下载及识别验证。
- OCR 识别和字段整理都有出错可能。缺失字段留空，低置信度文字、可能混淆的税号字符及金额不一致会提示核对；服务失败不会生成模拟数据，嘉宾/审核人须对照原票确认，不应仅凭 OCR 结果报销。
- 不支持 OFD、压缩包、身份证 OCR 或自动验真。OCR 不等于税务发票真伪核验。

## 已有访问保护

- 嘉宾邀请码验证；独立嘉宾会话只访问自己的文件。管理员另行登录；密码用 PBKDF2 加盐哈希保存。
- 会话 Cookie 为 HttpOnly、SameSite=Strict；管理员 8 小时、嘉宾 24 小时到期；拒绝跨站变更请求。独立草稿 Cookie 为 HttpOnly 随机凭证，有效期 30 天，个人信息与收款账号不写入 localStorage。
- 非公开随机文件标识、文件 MIME/后缀/内容检查、15 MB 单文件上限、每份申请最多 12 个文件（票据、行程单及支付截图合计）；支付截图限 JPG/PNG，每笔费用最多 3 张。
- 发票号码或已提交文件内容哈希重复时拒绝再次提交；幂等标记防止重复点击生成多笔。
- Excel 里用户文字明确为文本，避免公式注入；敏感 API 禁止缓存；有登录、审核、导出记录。
- 不收身份证号码或第三方平台密码。收款账号供报销汇款使用，完整账号仅由已登录的工作人员查看或导出；手机号进度查询不返回收款资料、票据、支付截图或文件链接。

正式上线需放在受控服务器，由 HTTPS 反向代理转发至本地端口，并设置 `COOKIE_SECURE=1`。应配置基础备份、主机访问权限和文件加密存储；核定哪些工作人员拥有管理端访问权。共用一个管理员账号无法区分具体操作人员，若多人长期使用应扩展独立账号。

提供 [Docker Compose 部署说明](DEPLOY.md) 和 [GitHub 上传步骤](GITHUB.md)。`GET /healthz` 和 `HEAD /healthz` 检查数据库可连接，只返回健康结果；数据库失败返回通用错误。限流默认使用直连 IP；只在 Compose 的应用端口不公开且 Caddy 覆盖 `X-Real-IP` 时启用 `TRUST_PROXY_HEADERS=1`，防止代理后的所有嘉宾共用同一限流额度。直接运行服务时应保持默认关闭。

## 收款信息与费用明细

新申请的单位为必填项；在顶层提交 `payment` 对象，必须选择银行卡或支付宝收款。字段如下：

| 字段 | 含义与要求 |
| --- | --- |
| `method` | `bank` 为银行卡，`alipay` 为支付宝。 |
| `accountName` | 银行卡收款人姓名或支付宝账户实名，必填。 |
| `accountNumber` | 银行卡号，或支付宝手机号/邮箱账号，必填。 |
| `bankName` | 开户银行；银行卡方式必填。 |
| `bankBranch` | 开户支行；银行卡方式选填。 |

收款信息与申请一起保存在私有数据目录。历史申请可能没有 `payment`，后台及导出应展示暂无收款信息，不能把旧资料当作已具备汇款条件。新申请缺少必填收款信息时不可提交。

管理员详情和 Excel 保留完整账号，用于财务审核及汇款；手机号进度查询不返回账号，即使脱敏的收款信息也不在该查询结果中展示。导出文件和 ZIP 包同样含个人信息，需要控制下载后的访问和流转。网站不会自动执行转账，工作人员仍须确认收款人与报销申请一致。

费用按独立卡片提交，支持住宿、机票、高铁、打车和其他类别，每笔分别记录金额、用途及对应票据。同类可有多笔，界面按类别汇总；行程单等补充附件归属相应费用，不重复计入金额。每笔可选传最多 3 张 JPG/PNG 支付截图，不作为额外费用，也不重复计入金额。票据、行程单及支付截图合计不得超过每份申请 12 个文件。工作人员后台可查看支付截图，Excel 导出记录截图关联信息，ZIP 归档包含截图原文件。OCR 只辅助提取票面字段，费用用途和报销归类由嘉宾填写、工作人员核对。

## 手机号进度查询

提交成功后，页面提示嘉宾使用本次填写的手机号查询处理进度。查询只接收手机号，不要求申请编号；同一手机号关联多份申请时返回申请列表，每份仅展示处理状态、金额、备注及时间。

进度查询不返回申请人的完整资料、收款信息、票面字段、文件标识或下载链接，也不允许读取票据与支付截图。完整资料及原件访问继续使用工作人员登录和私有文件权限保护。

## 服务端草稿

自动草稿在服务端保存尚未完整填写的基本信息、收款资料、费用明细及已上传文件的引用。草稿允许缺少提交所需的必填项，正式提交时仍须完成单位、收款等校验。客户端只通过有效期 30 天的 HttpOnly 随机草稿 Cookie 关联草稿，不把姓名、联系方式、银行卡号等内容写入 localStorage。

“上一步”“下一步”往返、刷新页面，以及关闭后在同一浏览器重新打开时，可继续已成功保存的资料。界面显示保存状态，保存失败可重试。嘉宾认证有效期为 24 小时，认证过期需要重新输入邀请码，不会因此清除服务端草稿。删除 Cookie、换浏览器或换设备后，不能自动关联原草稿。

草稿不保存邀请码、管理员密码或同意勾选；恢复后提交前须重新确认同意。已成功上传的文件可以恢复关联，未完成的网络上传不保证恢复。提交成功后清理对应草稿，但不会删除刚提交的申请、票据或原有已提交记录。

## 数据留存

`data/` 内含原票据、支付截图、联系方式、完整收款信息和服务端草稿，必须加入 `.gitignore`，不得上传 GitHub。数据库与文件目前未做应用层加密，私有目录与登录保护不等同于加密存储。导出的 Excel、ZIP 和备份也应视为敏感数据，不能随源码公开或上传仓库。正式使用前由会务/财务确定保留期；财务归档完成后清理服务器副本及备份。当前版本不自动删除已提交数据，避免误删财务材料。尚未提交的草稿文件可以在界面手动移除；草稿 Cookie 到期或被删除不等于服务端草稿与文件已被清除。

## 验证

```sh
python3 -m unittest discover -s tests -v
```

先安装 `requirements-dev.txt`。验证只用虚构数据、临时目录和临时本机端口，覆盖提交、登录、跨站拦截、文件访问隔离、无效文件、金额检查、重复票据、人工审核、补充附件、原始文件打包以及真实 Excel 导出。测试 PDF 的生成使用 reportlab（仅测试依赖）。

## 工作人员删除与恢复

`DELETE /api/admin/submissions/:id`（JSON 空对象）将申请标记为已删除，`POST /api/admin/submissions/:id/restore` 恢复，均须工作人员会话并校验同源。操作可重复请求，审计只记录实际变更。`GET /api/admin/submissions?deleted=1` 仅工作人员可查看回收站；已删除记录不进入正常统计、Excel/ZIP 导出和两种嘉宾进度查询，即使导出 URL 加 `deleted=1` 也不会包含回收站。

此功能为可恢复删除：保留数据库内容和附件文件，已删除申请的文件对嘉宾停用，工作人员仍可查看。重新上传和提交票据时，只与有效申请进行已提交重复校验；恢复记录在数据库写事务内检查与有效申请的附件哈希和发票号码冲突，阻止重复报销。已删除记录不能审核或通过旧幂等请求重新变成有效申请。当前不提供永久删除或自动清空回收站。
